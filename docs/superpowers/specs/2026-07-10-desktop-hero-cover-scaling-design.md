# 电脑端详情页 hero 封面放大设计

## 目标

在电脑端详情页中，当 hero 右侧信息量不足、出现明显留白时，改成更接近成熟漫画站的 `左侧大封面 + 右侧信息纵向排满` 结构。

本次不重做 hero 信息架构，只调整比例和排版密度：

- 中等桌面：封面小幅放大
- 大屏桌面：封面明显放大
- 标题超过 3 行时截断
- 手机端不动

## 设计决策

### 布局策略

采用固定断点放大，而不是按内容高度做动态计算。

原因：

- 稳定，不容易出现边界抖动
- 更适合 Remix 当前静态渲染和现有 CSS 结构
- 与现在的 hero 组件结构兼容，不需要新增运行时测量逻辑

### 用户已确认的方向

- hero 结构：`左侧大封面 + 右侧信息纵向排满`
- 桌面规则：`中等桌面小幅放大，大屏明显放大`
- 右侧信息区：`保持现在的信息量，只靠放大封面解决留白`
- 标题：`超过 3 行时省略`

## 实施范围

只改详情页桌面端 hero 的排版比例与标题截断。

涉及：

- `app/styles/app.css`
- 如有必要，少量调整 `app/routes/manga.$id.tsx` 的 class 使用

不涉及：

- 手机端 hero 结构
- hero 内按钮逻辑
- facts、标签、下载状态区内容结构
- 详情页正文和评论区

## 具体方案

### 中等桌面

在 `720px+` 的桌面区间：

- 增大封面列宽
- 缩小左右列之间的视觉落差
- 让封面更接近右侧主信息块高度

这里的放大是温和的，目标是减少“封面缩在角落”的感觉。

### 大屏桌面

在 `1180px+` 的大屏区间：

- 进一步扩大封面列宽
- 压缩 hero 外层无效留白
- 让封面在视觉上更接近 hero 主体高度

这里不追求严格等高，而是追求“视觉贴齐”，避免右侧大片空白。

### 标题处理

桌面端标题改为最多 3 行：

- 超过 3 行后省略
- 使用现有多行截断方式，不引入 JS 测量

手机端保持当前策略，不做同步收紧。

## 验收标准

- 电脑端详情页中，封面明显比当前更大
- 中等桌面与大屏桌面有两档不同的封面放大幅度
- hero 右侧留白显著减少
- 标题超过 3 行时正确省略
- 手机端布局无变化
- 不引入新的运行时计算或明显性能开销

## 风险与约束

- 如果个别作品右侧信息过多，封面放大后可能压缩标题区域，因此只做分档放大，不做极端等高
- 如果 hero 外层 padding 过大，单纯放大封面仍可能残留空白，因此可能需要同步微调桌面端容器 padding
- 当前实现优先稳定和高性能，不做基于真实内容高度的动态适配

## 推荐落地顺序

1. 调整 `720px+` 的封面宽度与 hero 间距
2. 调整 `1180px+` 的封面宽度与容器 padding
3. 给桌面端标题加 3 行截断
4. 对比中等桌面与大屏效果，微调到两档差异明确但不过度
