# JM Aura Remix 内容优先紧凑化重设计

## 背景

当前 Remix 前端已经完成了一轮结构重构，具备：

- 双主题与 Safari 适配基础
- 首页聚合流
- 搜索 / 发现 / 详情 / 阅读器 / 我的页完整路由
- 收藏、任务、导出、阅读状态等基础能力

但在真实使用中，界面仍然存在明显问题：

- 信息密度偏低
- 卡片、标题、留白整体偏大
- 多个页面带有过多解释性文案，像“落地页模块”而不是内容工具
- 搜索页和发现页把过多功能直接摊在主界面上，影响阅读和浏览效率
- 阅读器仍带有卡片化、圆角化和装饰性容器，不符合原生 Webtoon 阅读习惯

用户已经明确给出新的设计方向：

1. 保留当前顶栏
2. 首页整体方向参考 `JM-Aura/frontend`
3. 首页改为 **内容流优先**
4. 搜索与发现改为更紧凑的工具型界面，并把高级筛选收进二级入口
5. 清理宣传语和解释性块
6. 整体缩放与卡片尺寸收紧
7. 阅读器改成真正的原生 Webtoon 风格，并参考 `JM-Aura/frontend` 的阅读器能力增强

## 目标

### 产品目标

将现有前端从“结构完整但偏展示型”的界面，调整为：

- 更像真实内容工具
- 更像漫画 Web App
- 更接近 `JM-Aura/frontend` 的高密度内容浏览体验
- 同时保留 Remix 的原生路由、数据加载和现有后端接入方式

### 体验目标

- 首页首屏优先展示内容，而不是说明
- 搜索、发现、详情的主界面只保留最关键的操作
- 筛选进入二级层，减少主界面拥挤感
- 页面文案尽量服务于状态与操作，而不是“介绍自己”
- 阅读器以长时间阅读舒适度、连续性和低干扰为第一优先级

### 工程目标

- 保持现有 Remix 架构不变
- 保持现有后端 API 接入方式不变
- 在不推倒重来的前提下，完成一轮高质量 UI/信息架构收紧
- 优先改造用户感知最强的页面与组件

## 设计方向

本次设计方向定义为：

**中对齐 `JM-Aura/frontend` 的内容工具型重设计。**

含义是：

- 借鉴 `JM-Aura/frontend` 的首页节奏、卡片密度、信息取舍、阅读器风格
- 不进行 1:1 旧界面复刻
- 保留当前 Remix 前端已有的顶栏、路由结构、状态管理和后端契约
- 重新组织页面排版，让界面更现代、更干净、更接近原生 Web App

## 范围

本轮设计覆盖以下页面：

- 首页
- 搜索页
- 发现页
- 详情页
- 阅读器

本轮明确不作为主要修改对象的内容：

- 顶栏
- 主题系统总体架构
- 我的页主体结构
- 后端接口协议

## 总体原则

### 内容优先

页面优先展示漫画内容、章节内容和操作入口，而不是说明性文案。

### 更紧凑

标题、按钮、卡片、区块留白统一收紧一档，但不牺牲点击区域和触控可用性。

### 二级筛选

高级筛选和次要控件不直接摊在主界面，而是进入抽屉式二级层。

### 更像工具，不像落地页

减少每个模块的“解释自己”的文字；保留真正必要的：

- 状态提示
- 错误提示
- 空态提示
- 操作标签

### 阅读优先

阅读器以“原生连续阅读、低干扰、可长时间使用”为设计第一原则。

## 首页

### 目标

首页改为 **内容流优先**，而不是“继续阅读 Hero 优先”。

### 结构

首页首屏改为：

- 最新更新内容流
- 热门 / 推荐内容流
- 分类快速入口
- 缩小后的继续阅读模块

### 首页中保留的内容

- 最新内容
- 热门内容
- 分类快捷入口
- 小型继续阅读功能块
- 必要的快速搜索入口

### 首页中删减的内容

- 大段理念式说明
- 各区块的宣传语
- 过度放大的 hero 文案
- 过重的模块解释

### 卡片策略

- 首页漫画卡片缩小
- 同屏显示数量提高
- 只保留必要元信息
- 卡片正文以标题为核心
- 减少过多描述和说明区

### 风格参考

首页整体节奏参考 `JM-Aura/frontend/home.html` 一类内容流布局，但使用当前 Remix 组件体系重新组织。

## 搜索页

### 目标

搜索页变为真正的检索工具页，而不是“搜索说明 + 筛选说明 + 结果说明”的混合页。

### 主界面结构

第一层只保留：

- 搜索框
- 搜索按钮
- 筛选按钮

### 筛选策略

用户已经明确选择：**抽屉式二级筛选**

因此搜索页的高级筛选将进入抽屉，包含：

- 搜索范围
- 排序方式
- 时间范围
- 其他次级选项

### 结果区原则

- 结果区优先展示内容
- 卡片密度提高
- 结果说明尽量减少
- 不再在主界面堆叠多块解释性文字

### 文案策略

不再“教用户怎么搜”，默认用户就是带着检索意图来的。

## 发现页

### 目标

发现页继续承接 `category / sub_category / order_by / time / page`，但变成更纯粹的浏览型页面。

### 主界面结构

- 一条更紧凑的分类切换带
- 一个筛选按钮
- 高密度内容流

### 子分类策略

- `sub_category` 进入筛选抽屉
- 不再为每个分类写大段说明
- 有建议值时在抽屉里优先展示
- 无建议值时允许用户手动输入

### 内容区

- 更紧凑
- 更平
- 更连续
- 更像分类浏览工具，而不是内容介绍页

## 详情页

### 目标

详情页从“说明较多的展示页”收紧为“快速做决定的内容页”。

### 顶部结构

顶部区域保留：

- 封面
- 标题
- 少量元信息
- 动作区

动作区继续保留：

- 继续阅读
- 从第一话开始
- 收藏
- 导出

### 中部内容

中部直接进入：

- 简介
- 标签
- 章节列表

### 章节列表

章节列表目标是更适合快速扫读：

- 行高更紧凑
- 当前阅读位置更清晰
- 不额外配大量说明块
- 更像原生列表，不像内容展示模块

## 阅读器

### 目标

阅读器改成真正的 **原生 Webtoon 模式**。

### 强约束

阅读器必须满足：

- 图片无圆角
- 图片无卡片容器
- 图片之间没有多余空隙
- 图片以连续长流形式展示

### 页面层级

阅读器分为三层：

1. 阅读内容层
2. 顶部轻控件层
3. 底部功能栏

### 阅读内容层

- 图片 full-width 顺序排列
- 去掉卡片式容器
- 去掉装饰性背景和阴影
- 连续阅读优先

### 顶部轻控件层

- 返回
- 当前章节信息
- 轻量菜单入口

### 底部栏

底部栏需要重新设计，重点强化：

- 章节切换
- 宽度调节
- 当前阅读状态
- 控件显隐
- 阅读进度反馈

### 功能增强方向

参考 `JM-Aura/frontend/views/reader.html`，但坚持原生 Remix/React 实现。

优先保留或增强：

- 章节切换
- 阅读进度显示
- 阅读偏好持久化
- 控件自动隐藏与唤出
- 更清晰的状态反馈

### 设计原则

阅读器不是展示型页面，任何装饰性设计都不能干扰连续阅读。

## 缩放与密度规则

### 全局缩放

整体收紧一档：

- 标题缩小
- 卡片缩小
- 区块间距减少
- 页面 padding 减少
- 次级信息字体减轻

### 漫画卡片

- 首页、搜索、发现的漫画卡片统一缩小
- 更接近 `JM-Aura/frontend` 的内容密度
- 大屏优先一屏展示更多内容

### 文案规则

保留：

- 状态文案
- 错误文案
- 空态文案
- 必要标签

删除或大幅缩减：

- 宣传语
- 解释每个功能块“为什么存在”的文字
- 类落地页文案

## 组件与样式策略

### 优先修改的文件

#### 首页与密度

- `app/routes/_index.tsx`
- `app/components/home.tsx`
- `app/components/primitives.tsx`
- `app/components/media.tsx`
- `app/styles/components.css`
- `app/styles/shell.css`
- `app/styles/app.css`

#### 搜索与发现

- `app/routes/search.tsx`
- `app/routes/discover.tsx`
- `app/components/discover.tsx`
- 新增筛选抽屉组件（放在 `app/components/`）

#### 详情与阅读器

- `app/routes/manga.$id.tsx`
- `app/routes/chapter.$id.tsx`
- `app/styles/reader.css`
- `app/lib/reading-state.ts`

### 样式原则

- 保持现有 token 体系
- 收紧尺寸、间距和层级表达
- 减少内联样式
- 优先以 class 驱动页面密度与布局调整

## 分批实施建议

### 第一批

- 首页
- 搜索页
- 发现页
- 全局卡片 / 标题 / 间距缩放

目标是先解决“看起来像展示页、说明太多、密度太低”的问题。

### 第二批

- 详情页
- 阅读器
- 底栏状态与阅读器功能增强

目标是再解决“进入作品后的阅读链路体验”。

## 风险与约束

### 风险 1：界面收紧后点击区域变差

缓解方式：所有收紧都不得牺牲触控区域和可点击性。

### 风险 2：阅读器变原生后功能退化

缓解方式：阅读器不是只改样式，还必须同步保留并增强章节切换、状态显示与阅读偏好。

### 风险 3：过度贴近旧前端而失去当前架构优势

缓解方式：只借鉴 `JM-Aura/frontend` 的内容节奏与界面取舍，不照搬旧实现。

## 最终结论

本轮重设计的目标是：

**保留当前 Remix 顶栏与架构，把首页、搜索、发现、详情和阅读器统一拉回内容优先、高密度、低解释、强工具感的漫画 Web App 方向，并把阅读器真正改造成原生 Webtoon 模式。**
