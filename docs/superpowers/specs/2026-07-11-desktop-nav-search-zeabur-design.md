# 桌面顶栏、搜索修复与 Zeabur 部署整理设计

日期：2026-07-11  
项目：`JM-Aura-Remix`

## 背景

当前项目已经完成了移动端优先的内容浏览、下载任务与账户页面，但还有五个影响上线体验的问题：

1. 首页和桌面端顶栏搜索框提交后，没有稳定触发搜索页刷新。
2. 桌面端顶栏仍然偏移动端思路，缺少适合大屏的主导航与二级菜单层次。
3. 项目准备部署到 Zeabur，需要整理成前后端双服务可部署结构。
4. 根目录仍混有旧项目与历史产物，不适合直接发布到 GitHub。
5. 当前仓库缺少一份能同时承担发布说明与工程文档职责的新版 README。

本次设计目标是在保持 Remix 性能优势和当前手机端交互不回退的前提下，完善桌面端导航、修复搜索提交、补齐 Zeabur 部署配置，并整理仓库结构。

## 目标

- 修复首页和桌面顶栏搜索提交后页面不刷新的问题。
- 桌面端顶栏重构为更清晰的大屏导航结构。
- 手机端顶栏保持不变。
- 头像入口替代“我的”主导航位，并提供二级菜单：
  - 设置
  - 下载
  - 收藏
- 项目支持 Zeabur 前后端双服务部署。
- 根目录整理为适合 GitHub 发布的主项目结构。
- 重写双语 README，明确 `v3.0.0` 全面重构、与 `JM-Aura/` 的差异、部署方式与使用方式。

## 非目标

- 不实现联想搜索或输入即搜。
- 不改动手机端顶栏布局。
- 不将前后端重新合并成单服务部署。
- 不做新的设计系统或整站大规模视觉重做。
- 不维护多份内容重复的 README 变体。

## 设计概览

本次改动拆成五块：

1. 搜索提交流程修复
2. 桌面端顶栏重构
3. Zeabur 双服务部署支持
4. 仓库根目录整理
5. README 重写

其中：

- 搜索和顶栏重构只调整桌面端主壳层，不影响手机端导航。
- 部署支持通过环境变量解耦前端与 API 服务地址。
- 仓库整理采用“归档/移出无关目录”的方式，不做激进硬删。
- README 采用“发布说明 + 工程文档”结合写法，面向 GitHub 首页和实际部署使用。

## 搜索修复

### 目标行为

首页搜索框和桌面顶栏搜索框统一行为：

- 用户输入关键词
- 点击提交或按回车
- 导航到 `/search?q=关键词`
- 搜索页通过 URL 参数驱动 loader 刷新并展示结果

### 实现原则

为了保持 Remix 高性能和稳定刷新：

- 优先使用标准 `<Form method="get">`
- 让 URL 查询参数成为单一事实来源
- 不依赖手写 `window.location` 或复杂客户端状态同步

### 结果

这样可以避免以下问题：

- URL 变化但页面未刷新
- 表单提交被组件状态截断
- 同一搜索框在不同页面行为不一致

## 桌面端顶栏

### 适用范围

- 仅桌面端重构
- 手机端顶栏保持现状

### 顶栏结构

桌面顶栏改为三段式：

1. 左侧：品牌与首页入口
2. 中间：主导航入口
3. 右侧：桌面搜索框 + 头像菜单

### 主导航

保留三个一级入口：

- 首页
- 搜索
- 发现

“我的”不再作为一级导航直接占位。

### 头像菜单

头像作为桌面端个人入口，点击展开轻量二级菜单：

- 设置
- 下载
- 收藏

说明：

- 设置对应当前手机端“我的”页面入口
- 下载跳转到 `me.tasks`
- 收藏跳转到 `me.favorites`

### 设计原则

桌面端顶栏遵循这些原则：

- 一级导航只保留高频内容入口
- 用户相关功能收敛进头像菜单
- 搜索作为桌面端高频功能放在右侧显著位置
- 不引入复杂全局弹层系统

## 性能要求

本次顶栏与搜索改造必须保持 Remix 高性能：

- 不增加全局状态管理器
- 不增加输入时联想请求
- 不增加高频事件监听
- 不增加复杂动画和长链路依赖

允许的轻量状态：

- 头像菜单开关状态
- 顶栏局部展开/关闭状态

搜索结果仍由路由 loader 驱动，不由顶栏自身维护结果状态。

## Zeabur 双服务部署

### 部署结构

项目按两个服务部署：

1. `web`
   - Remix 前端服务
   - 负责页面渲染与浏览器端入口
2. `api`
   - Hono API 服务
   - 负责登录、搜索、详情、下载任务与 ZIP 下载

### API 地址策略

采用环境变量注入 API 地址，而不是写死本地端口。

前端通过统一的 `API_ORIGIN` 解析逻辑：

- 本地开发：继续兼容 `3000 / 8787`
- Zeabur 部署：读取真实 API 服务域名

### 需要补的内容

- 前端服务启动命令与构建命令
- 后端服务启动命令与构建命令
- Zeabur 相关环境变量说明
- README 中的部署章节
- 如有必要，增加 `Dockerfile`、启动脚本或 `.zeabur` 配置文件

### 目标

做到以下几点：

- 本地开发仍可直接跑
- Zeabur 上可拆分成两个服务部署
- 配置方式尽量少且清晰

## 风险与取舍

### 不做联想搜索

联想搜索会增加输入期请求与状态复杂度，不适合本次“修复提交刷新”目标。  
本次只解决稳定跳转和结果刷新。

### 桌面端只做必要重构

顶栏只重构信息架构和排版，不做整站视觉翻新。  
这样风险更小，也更符合“最后完善工作”的范围。

### 维持双服务

虽然单服务部署更省事，但你已经确认前后端拆服务更适合后续维护，因此本次设计以双服务为准。

### 仓库整理不做激进删除

考虑到你可能仍需要参考旧目录，本次按“归档/移走”处理，而不是直接永久删除。

### README 采用双语组合写法

双语 README 会让文件更长，但这是有意取舍。  
相比维护多份 README，单文件双语更适合当前 GitHub 发布与 Zeabur 部署说明的统一维护。
